The pipeline and its failure points

RAG has five stages: ingest (parse to text) → chunk → embed (vectors) → retrieve (top-k search) → generate (answer with citations). Ninety percent of the time, a bad model answer is not the model's fault — it simply never received the right passage. The guiding rule: improve retrieval before you touch the generation prompt. Every dollar you spend on the generator prompt is worth a dollar; every dollar in retrieval is worth ten. Now let's talk about what actually decides the outcome.

Chunking: cutting without decapitating

Default: a fixed window of 500–1000 tokens with 10–20% overlap. This hurts on two fronts: a chunk that's too large dilutes the signal in the embedding; too small loses context. Upgrades that pay off: structure-aware splitting (markdown headers, table cells), semantic splitting by sentence, and late chunking, which embeds a paragraph with whole-document context. Keep metadata (filename, heading, chunk number) — without it there are no citations and no debugging.

`python

from langchain_text_splitters import MarkdownHeaderTextSplitter

splitter = MarkdownHeaderTextSplitter(['#', '##', '###'])

chunks = splitter.split_text(doc)

`

Embeddings and vector search

An embedding turns text into a vector; semantic closeness = geometric closeness (cosine). Common models: text-embedding-3, Cohere embed, BGE. Beginner mistakes: mixing embedding models between indexing and query time (must be identical), not normalizing vectors, and forgetting that a short query ('what's the price?') needs rewriting — a query template that turns it into a hypothetical answer paragraph. Test on your own data, not on someone's blog post.

`python

q = client.embeddings.create(model='text-embedding-3-small', input=query).data[0].embedding

hits = index.search(np.array(q), k=8)

`

Hybrid + reranking: the big upgrade

Vector search misses exact names, error codes, and technical terms — where BM25 wins. Hybrid search runs both and fuses rankings (RRF — Reciprocal Rank Fusion):

`python

def rrf(list_a, list_b, k=60):

scores = {}

for lst in (list_a, list_b):

for i, doc in enumerate(lst):

scores[doc] = scores.get(doc, 0) + 1 / (k + i + 1)

return sorted(scores, key=scores.get, reverse=True)

`

Then a cross-encoder reranker (Cohere Rerank, BGE-reranker) re-scores the 50 candidates and returns a far better top-3. This is the button that moves your RAG from 'decent' to 'good'.

Copy-ready prompt

Grounded answer prompt: ``` Answer only from the provided passages. Cite a passage ID after each claim, like [3]. If the passages do not contain the answer, write exactly: 'Not found in the documents.' Do not fill in from your general knowledge. ```

Query upgrade before retrieval: ``` Rewrite the user's question as a standalone 2–3 sentence search passage, including synonyms and relevant product codes. Return only the passage. ```
