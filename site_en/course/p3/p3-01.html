Tokens: the model does not see words

Every text you send is split into tokens — sub-word pieces. In English a word averages about 1.3 tokens; other languages often cost more because they're underrepresented in training data. The implication: pricing, context-window limits, and generation speed are all measured in tokens.

`python

import tiktoken

enc = tiktoken.encoding_for_model('gpt-4o')

print(len(enc.encode('Hello world, how are you?')))

`

Don't guess how many tokens you have — measure. It's the number that matters most on your invoice at the end of the month.

KV cache: why output tokens cost more than input tokens

During generation, the model keeps the keys and values of every token it has already seen in memory — that's the KV cache. Without it, we'd recompute all attention for every new token. Two practical conclusions: (1) output tokens cost more than input tokens; (2) the order of your prompt determines whether you get a discount. Identical prefixes (system prompt, static RAG headers, few-shot blocks) get automatic prompt caching with most providers — put the constant part first and the dynamic part last. Up to 90% off input, for free, provided you structure the prompt correctly.

temperature, top_p, and friends

The model computes a probability distribution over the next token. temperature flattens or sharpens it: 0 = nearly deterministic, recommended for extraction and code; 0.7–1.0 suits creative writing. top_p cuts the tail of the distribution — usually you should tune one of them, not both. Other players: max_tokens (a real cost ceiling), stop (cut wasted output), seed (reproducibility for experiments). A classic mistake: fixing bad output with temperature. It won't fix a bad prompt — it will just make it sound more confident.

What actually matters in practice

Priority order for a developer: (1) max_tokens — a ceiling on cost and on infinite loops; (2) temperature=0 for any flow that should be consistent; (3) prompt structure for caching; (4) stop sequences for fixed formats. Don't touch top_k without a good reason. And if the answers are bad — the problem is almost always the prompt, the tools, or the data, not the parameters.
