Capstone: Build and Deploy a Production Agent

🎯 What you'll be able to do: Take an AI agent from specification to production — including evaluation, monitoring, and documentation.
Roni · Play the lecturer

Stage 1: Specification — what does 'works' mean

Before a single line of code, write one page: what the agent does, for whom, its tools, and above all — how you'll know it's good. Testable targets: 'answers 85% of the golden set correctly', 'p95 under 6 seconds', 'average cost under X cents per request'. Explicit boundaries: what the agent never does ('never deletes files', 'never answers outside the documentation'). Pick one real, narrow task — a support agent for one product, a log analyzer, a PR summarizer. Narrow and good beats broad and sad. And yes, I'd also love an agent that does everything. After the capstone.

Stage 2: Building with guardrails

Architecture you already know from the course: one tool loop or router+specialists, RAG over one source, and structured output. Guardrails you may never skip: max_tokens on every call, an iteration ceiling per tool, a timeout on every MCP server, an allowlist for every network action, try/except that returns a detailed error to the model, and full logging of every round (input, tool calls, output, latency, cost).

`python

def handle(msg):

with trace(user=msg):

return agent_loop(msg, max_iters=10)

`

Good logging at this stage is the difference between a five-minute debug and five hours.

Stage 3: Evaluation before launch

A golden set of 30+ cases (from the evals lesson), a full run, and a clear report: accuracy, p95 latency, average cost, and agent-specific — tool-failure rate and percentage of requests requiring fallback. Security checks: run your injection attack against it and record that it holds. Only when the numbers meet the spec's targets do you move to deploy. If they don't, go back to the stage that needs it (search? prompt? model?). Deploying an agent without numbers isn't a release, it's a bet.

Stage 4: Deploy, monitor, maintain

Wrap it in an API (FastAPI) with one clean endpoint, auth, and streaming to the client. Daily monitoring: one dashboard with accuracy on a small canary run every hour, latency distribution, daily cost, tool-error rate, and an alert when anything drifts. Save every change in git with the score it got — so every model upgrade (and they will come) is measured against the same set. A README with the spec, the numbers, and the architecture — that's both your documentation and your portfolio. From here it's not a course anymore, it's work. And you're ready for it.

Copy-ready prompt

Specification template (fill in and save as SPEC.md): ``` # Agent: name ## Purpose: one sentence ## Tools: list + what each is allowed to do ## Quality targets: accuracy >= X% on a 30-case golden set ## Latency/cost targets: p95 <= X seconds, <= X cents per request ## Boundaries: what the agent never does ## Security: injection test passing? approved destinations list ```

Post-deploy smoke test (run on a cron): ```python def smoke(): ok = sum(run_case(c) for c in SMOKE_SET) / len(SMOKE_SET) if ok < 0.8: alert(f'agent degraded: {ok:.0%}') ```

The capstone: pick one real, narrow task, write SPEC.md from the template, build the agent (tools + RAG + structured output), evaluate on 30 cases, defend against injection, and deploy as an API with a smoke test. Submit: a repo link + a README with the numbers. That's your diploma.
