Function Calling End to End

🎯 What you'll be able to do: Build a correct tool loop — from function definition to execution, error handling, and parallel calls.

The contract: defining a tool properly

A tool is a regular function in your code plus a JSON schema definition the model sees. The description is the tool's prompt — the model decides from it when to call and when not to.

`python

tools = [{

'type': 'function',

'function': {

'name': 'get_weather',

'description': 'Current weather for a city. Use only when the user asks about specific weather.',

'parameters': {

'type': 'object',

'properties': {

'city': {'type': 'string'},

'units': {'type': 'string', 'enum': ['c', 'f']}

},

'required': ['city'],

'additionalProperties': False

}

}

}]

`

Precise verb names, enums over free strings, and one parameter = one responsibility.

The loop: where most people fall

It's not one call — it's a loop. The model returns tool_calls, you execute, return the result with role: 'tool', and repeat until the model sends a final answer.

`python

while True:

r = client.chat.completions.create(model=M, messages=msgs, tools=tools)

msg = r.choices[0].message

if not msg.tool_calls:

break

msgs.append(msg)

for tc in msg.tool_calls:

result = dispatch(tc.function.name, json.loads(tc.function.arguments))

msgs.append({'role': 'tool', 'tool_call_id': tc.id, 'content': json.dumps(result)})

`

A hard ceiling on iterations (10–15) is mandatory — an agent without a floor hurts itself, and your budget.

Errors are part of the protocol

The model doesn't run your code — you do. If a tool fails, don't throw an exception upward: return an error object to the model like {'error': 'city not found: did you mean Boston?'}. Models handle detailed errors excellently — they apologize, fix the parameter, and retry. What kills agents is generic errors ('something went wrong') that leave the model blind. Timeouts, empty results, quota overruns — everything goes back to the model as information. A good agent isn't one that never fails; it's one that recovers.

Parallel calls and limits

Modern models return multiple tool_calls at once — implement parallel execution (asyncio.gather) when the tools are independent; it saves seconds every turn. But: tools with side effects (sending email, charging, deleting) run serially or with user confirmation — parallel tool calls and double-sends is a true story that happened to everyone. Also remember every tool round adds tokens to the messages and the loop can bloat — minimize tool results (first 200 lines of a file, not the whole file).

Copy-ready prompt

Tool definition template (copy and adapt): ```python tool = { 'type': 'function', 'function': { 'name': 'search_docs', 'description': 'Searches internal documentation. Use for any question about product or policy.', 'parameters': { 'type': 'object', 'properties': {'query': {'type': 'string'}, 'top_k': {'type': 'integer', 'default': 5}}, 'required': ['query'], 'additionalProperties': False } } } ```

System prompt for a tool-using agent: ``` You are a support agent. Before answering, check whether a tool can provide current information. Never invent data — call the tool. If a tool fails twice, answer from what is known and mention the failure. Maximum 8 tool calls before a final answer. ```
