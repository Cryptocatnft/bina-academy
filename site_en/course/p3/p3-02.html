Structured Output Without Gambling: JSON, Schemas, and pydantic

🎯 What you'll be able to do: Make the model return data your code can trust — schema-defined JSON, validated, with retries handled.
Roni · Play the lecturer

Why prompting alone is not enough

Asking for 'JSON' in free text works most of the time — and most of the time isn't enough for production. The model can wrap in prose, add comments, forget a field, or invent a new enum value. The rule: anything your code needs to parse must be defined by contract — a schema. A prompt explains what's nice; a schema enforces what's correct. The winning combo: a strict schema in the API plus pydantic validation on your side, because two layers of safety always beat one.

JSON mode vs strict schema

Most providers offer two levels: json_mode (guarantees valid JSON but not shape) and json_schema (strict — output must conform to the schema, including additionalProperties: false). Always prefer the strict schema.

`python

client.chat.completions.create(

model='gpt-4o-mini',

messages=[...],

response_format={

'type': 'json_schema',

'json_schema': {

'name': 'meeting',

'strict': True,

'schema': {

'type': 'object',

'properties': {

'date': {'type': 'string'},

'participants': {'type': 'array', 'items': {'type': 'string'}}

},

'required': ['date', 'participants'],

'additionalProperties': False

}

}

}

)

`

pydantic as the layer of truth

Even with a strict schema, the final truth is on your side. pydantic validates types, ranges, and constraints at runtime — and libraries like instructor wire it straight into the API with an automatic retry loop.

`python

from pydantic import BaseModel, Field

class Meeting(BaseModel):

date: str

participants: list[str] = Field(default_factory=list)

action_items: list[str]

m = Meeting.model_validate_json(raw)

`

Tip: field descriptions in the schema are part of the prompt — they affect extraction quality just as much as your instructions.

Where to be careful

Three traps: (1) large enums — the model will miss rare values, provide examples; (2) many optional fields — the model tends to leave them empty; if it matters, make it required with a default like 'unknown'; (3) deep nesting — flatten the schema, a list of shallow objects beats a three-story tree. And the retry loop: at most 2–3 attempts, with the validator's error message fed back as the next message — models self-correct beautifully when you show them what broke.

Copy-ready prompt

Meeting-summary extraction with a strict schema: ```python schema = { 'name': 'meeting_summary', 'strict': True, 'schema': { 'type': 'object', 'properties': { 'date': {'type': 'string', 'description': 'YYYY-MM-DD or unknown'}, 'participants': {'type': 'array', 'items': {'type': 'string'}}, 'action_items': {'type': 'array', 'items': {'type': 'string'}} }, 'required': ['date', 'participants', 'action_items'], 'additionalProperties': False } } ```

Helper prompt for extraction (place before the text): ``` Extract the date, participants, and action items from the meeting transcript. If information is missing, return 'unknown' — never guess. Names must appear exactly as written in the text. ```
