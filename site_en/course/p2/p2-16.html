Portfolio Project 4: Data-Cleaning Agent

🎯 What you'll be able to do: Build an agent that fixes messy data — validating, correcting, and auditing CSV records — with an audit trail no spreadsheet jockey can match.
Alex · Play the lecturer

Step 1: Your messy dataset (20 min)

Generate (or download) a realistic dirty CSV — customer records are ideal: 200+ rows with inconsistent names ("Dana LEVI", "dana levy"), emails in five formats, dates in three conventions, missing phones, duplicated rows, and a category field where 'corporate', 'Corporate', and 'B2B' all mean the same thing. Realism is everything here — this exact mess is what every operations team actually lives with. Define the target schema: the clean field names, formats, and allowed values — your canonical 'single source of truth.' Write your cleaning rules in plain language: how names are normalized, what counts as a duplicate, what to do with a missing email. Rules first, agent second. Always.

Step 2: The cleaning loop (45 min)

The agent processes records in small batches — 10-25 rows at a time, to keep context clean (Lesson 3 forever). For each batch it returns structured JSON (Lesson 5): the corrected record, a list of changes made, a confidence level per change, and a needs_human flag for anything ambiguous — a duplicate that might actually be two people, an email with a likely typo. Two golden rules: never silently invent data (missing phone stays missing, flagged) and every change gets a reason ("field": "email", "change": "fixed typo dana@gmial.com → dana@gmail.com", "confidence": "high"). That change log is the entire soul of this project — it's what turns 'AI touched my data' from a threat into an audited blessing.

Step 3: Validation and the audit trail (45 min)

Cleaning without validation is just different dirt. Build checks: email format regex, dates parse to ISO, every category is in the allowed list, no duplicate IDs survived. Run the checks *after* the agent and log results — a validation report, not a vibe. Then assemble the audit trail: a spreadsheet of every change (row, field, before, after, reason, confidence), plus summary stats — rows processed, changes by type, records flagged for human review. Export three artifacts: clean_data.csv, change_log.csv, validation_report.md. Compare effort and error rate against cleaning 50 rows by hand — that comparison is your results section. 'What took 6 hours now takes 12 minutes with a full audit log' is a sentence that gets people hired.

Step 4: README, and looking ahead (30 min)

Write the README around the audit trail: problem (messy data, fear of AI changes), solution (rules + LLM judgment + validation + full change log), architecture diagram, results with your real numbers, decisions (why batch size, why flags instead of guesses), limitations (what it shouldn't touch — financial records without review), next steps. Record a 60-second demo: dirty rows in, clean CSV + change log out. That's portfolio artifact #4 — four of five, with project five, your personal assistant agent, waiting as the course-final in Lesson 24. This data-cleaner becomes its skill: your final agent will know how to fix a spreadsheet, triage an inbox, and summarize documents. Keep the files; the band gets back together soon.

Copy-ready prompt

Clean these customer records. Return ONLY JSON lines, one per record: {"id": ..., "clean": {"name": ..., "email": ..., "date": "YYYY-MM-DD", "category": one of [corp, smb, personal]}, "changes": [{"field": ..., "before": ..., "after": ..., "reason": ..., "confidence": "low|medium|high"}], "needs_human": true/false} Rules: never invent values; normalize dates to ISO; if unsure, set needs_human=true. Records: [PASTE ROWS]

Here are my cleaning rules and a sample of change logs: [PASTE BOTH]. Find the 3 riskiest patterns in the changes — places where the agent might be wrong — and write one additional rule to prevent each.

Ship the data-cleaner: dirty dataset of 200+ rows, cleaning rules documented, batch loop with JSON change logs, validation checks, and the three output files. Include your manual-vs-agent comparison numbers in the README. Archive everything — your final-project agent will reuse this skill.
