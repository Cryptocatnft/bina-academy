Why JSON runs the world

JSON — JavaScript Object Notation — is the universal format that software uses to exchange data: {"name": "Alex", "score": 8}. When AI outputs JSON, it can flow straight into a spreadsheet, a database, a website, or the next step of an automation. The moment your AI output has a schema, you've moved from *chat* to *pipeline*. Every serious AI product — support triage, lead enrichment, document processing — is structured outputs under the hood. If you learn one pro skill from this module, make it this one.

Anatomy of a schema prompt

A production-grade structured prompt has four parts:

1. The task in plain words.

2. The exact schema — field names, types, allowed values. Be pedantic.

3. Rules for uncertainty — what to do with missing data (null, "unknown", empty array — pick one and enforce it).

4. An example — one fully filled, valid output.

Example field spec: "sentiment": one of "positive" | "negative" | "neutral" | "mixed". Give the model an explicit vocabulary and it stops inventing its own. The model will match your example's shape almost perfectly — that's the few-shot force you'll sharpen in Lesson 6.

Validation: trust, then verify

Even with a perfect prompt, models occasionally emit broken JSON — a stray comma, a comment, markdown fences around the output. The pro habit: always validate. Paste into a JSON checker, or in code run json.loads() and catch the error. Defensive rules for prompts: "Return ONLY raw JSON, no markdown, no commentary, no code fences." And design schemas that are forgiving by design: enums instead of free text, numbers where possible, and an "uncertain_fields" array so the model has somewhere honest to put doubt. Failures should be detectable, not silent.

Beyond JSON

The same discipline applies to other formats: CSV rows for spreadsheets, YAML for config, SQL the model writes for you, even strict XML when an old system demands it. The principle is constant: decide the shape first, then prompt for it. Also note: many APIs and chat tools now offer a native "structured output" or JSON mode — use it when available, but know how to do it by hand, because interviews and legacy systems won't always hand you the easy button.

Copy-ready prompt

Extract structured data from the text below. Return ONLY raw JSON (no markdown fences, no commentary) matching exactly this schema: {"company": string, "industry": string, "urgency": "low"|"medium"|"high", "key_points": string[], "next_action": string, "missing_info": string[]} Rules: use null for anything not stated. Do not guess. If a value is ambiguous, put it in missing_info instead. Text: [PASTE TEXT]

Act as a strict validator. Here is my JSON schema: [PASTE SCHEMA]. Here is AI-generated output: [PASTE OUTPUT]. List every field that violates the schema, every hallucinated value, and return the corrected JSON.

💪 Exercise

Take 5 real emails or messages. Write a schema prompt that extracts each into JSON with fields like sender_intent, urgency, deadline, action_items. Run all 5, then validate every output in a JSON checker. Record your error rate and fix your prompt until all 5 parse cleanly.
