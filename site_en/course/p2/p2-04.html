Hallucinations and How to Catch Them

🎯 What you'll be able to do: Understand why models invent facts, and learn the professional verification techniques — grounding, citations, self-checks, evals — that make AI output trustworthy enough to deploy.
Alex · Play the lecturer

Why models invent things

A hallucination is output that is fluent, confident, and wrong. The model isn't lying — it's completing a pattern. When training data was thin or contradictory, the most *plausible* continuation may be invented: a fake API method, a plausible-but-wrong statistic, a citation to a paper that doesn't exist. Classic danger zones: specific numbers, names, dates, quotes, citations, API function signatures, and 'questions where the honest answer is I don't know.' A model asked 'what did the CEO say in the 2024 memo' will often *invent* a quote rather than admit ignorance. Knowing these zones tells you where to point your checks.

Grounding: the professional fix

The industry-standard answer to hallucination is grounding: make the model answer from provided, verified sources rather than memory. Paste the actual memo; retrieve the actual documentation; fetch the live data via a tool. Then instruct: 'Answer ONLY from the provided sources. If the answer is not in them, say so.' Grounded systems are measurably more accurate — and they cite their sources, so a human can verify in seconds. This pattern is RAG (Lesson 9) plus a guardrail, and it's exactly what interviewers mean when they ask 'how do you prevent hallucinations?' Write that answer down now.

Catching errors in your own workflow

Habits that catch hallucinations before they ship:

  • Specificity check: treat every number, name, URL, and citation as guilty until verified. Verify the top three, spot-check the rest.
  • Ask for confidence and citations: 'List each claim with a confidence level and its source' — then check the sources exist.
  • Adversarial prompt: 'Critique your own answer above. What might be wrong or unsupported?'
  • Second-model check: run the output past a different model or a web search.
  • Code is self-verifying: run it. Tests catch hallucinated APIs instantly — one reason shipped, tested code is your strongest portfolio evidence.

From habits to systems

Personal habits don't scale to production. Companies deploy AI behind evals — automated test suites for AI output (Lesson 12): golden questions with known answers, LLM-as-judge checks for faithfulness to sources, and observability dashboards that flag suspicious answers. When an employer asks 'how do we trust this agent?', your answer is a pipeline: grounded generation, citations, automated checks, human review for high-stakes answers. That answer is worth salary. For now: every prompt you write in this course should end with a verification step. Make it a reflex.

Copy-ready prompt

Answer this question ONLY from the sources I paste below. After each claim, add [S1], [S2] etc. for the source you used. If the sources don't contain the answer, say 'not in sources.' Question: [QUESTION] Sources: [PASTE SOURCES]

Critique your previous answer like a skeptical senior reviewer: list every claim that is uncertain, unsourced, or possibly fabricated, and rate each as verified / plausible / suspicious.

Here is a list of 5 facts you told me: [LIST]. For each, tell me whether you are confident from training data, guessing, or extrapolating — be brutally honest.

💪 Exercise

Deliberately trigger a hallucination: ask an AI for 'three academic papers about [niche topic] with authors and years.' Then verify each one with web search and record how many were real. Write a 4-sentence reflection on what this means for using AI at work — and keep it; it's a killer interview story about why you build grounded, evaluated systems.
