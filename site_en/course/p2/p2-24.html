The exam: what it covers and how to review

The certificate exam checks working understanding, not memorization. Areas, mapped to modules: LLM fundamentals — tokens, context, hallucinations, grounding (Lessons 1, 3–4); Python and API practice — schemas, retries, cost control (5–7); RAG — chunking, embeddings, vector search, citations (9); deployment — FastAPI, Docker, CI (10); agents — function calling, LangGraph, MCP, safety gates (11); evals — golden sets, LLM-as-judge, traces (12); career — market data, ATS keywords, interview structure (2, 17, 22). Review method: for each area, explain it out loud in 60 seconds without notes — the same fluency the interviewers will test. Where you stall, re-read that lesson's sections and re-run its exercise. Your projects are your notes: every concept is something you shipped.

The submission package

Final submission checklist — everything due together:

  • Capstone repo: assistant agent with memory, tools, MCP server — passing CI with evals.
  • Deployed URL: live and health-checked (Lesson 20's uptime monitor running).
  • Demo video: the 3-minute walkthrough from Lesson 16.
  • Design-decisions doc: one page, what you chose and rejected, and why.
  • Portfolio set: all four project repos passing the Lesson 20 quality bar, pinned, with the profile README.
  • Career assets: master CV, LinkedIn optimized, one application already sent (Lesson 21's exercise).

Verify like an engineer would: run every link from an incognito browser, run gitleaks, re-run the CI suites. If the package passes your own review, it passes ours.

Where you now stand

Look at what you can put on a CV, with links: Python, structured LLM outputs, RAG built from scratch, FastAPI + Docker + CI deployment, LangGraph agents, LangChain, function calling, MCP servers, evals and observability — mapped almost one-to-one onto the 2026 demand list: Python (50% of agentic postings), cloud (34%), MCP (27%), RAG (26%), LangChain (15%), LangGraph (13%), vector DBs (13%), tool use (11%), evals (9%). Four deployed systems with public URLs — when only ~4% of AI-engineer postings are entry-level, shipped proof is exactly how you compete. And the working habits — test it, measure it, cite it, ship it — are the ones employers keep. That combination is your credential; the certificate just makes it official.

The 30-day sprint

Passing the exam is a milestone, not a finish line. Run the next 30 days like a project:

  • Week 1: five tailored applications to Lesson 2 target companies; share the capstone demo on LinkedIn; tell your network you're looking.
  • Week 2: five more applications plus direct outreach — three short messages (Lesson 19 formula) to engineers at target companies; keep one build-in-public post a week.
  • Week 3: keep the AI-interviewer drills at twice a week until offers arrive; do one timed take-home simulation if any are pending.
  • Week 4: iterate on feedback — track which applications convert, fix your weakest interview answer, and consider the internal-transfer path (Lesson 21, bucket 4).

Treat 'land the role' exactly like your capstone: scope it, measure it, ship it.
