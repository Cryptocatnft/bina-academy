FastAPI in fifteen minutes

FastAPI turns a function into a URL:

`python

from fastapi import FastAPI

from pydantic import BaseModel

app = FastAPI()

class Ask(BaseModel):

question: str

class Answer(BaseModel):

answer: str

sources: list[str]

@app.post("/ask", response_model=Answer)

def ask(body: Ask) -> Answer:

hits = retrieve(body.question)

return Answer(answer=generate(body.question, hits),

sources=[h["id"] for h in hits])

`

Pydantic (Lesson 7) validates both directions automatically, and /docs gives you a live test page for free. Load the index at startup, not per request, and add a /health endpoint — deploy platforms ping it. This is the exact shape of every AI microservice you'll build in Module 4.

Docker: the shipping container

'Works on my machine' is not a deployment. Docker packs your app + Python + dependencies into one image that runs identically on your laptop, a cloud VM, or a Kubernetes pod (that last one is 21% of agentic postings — this lesson is your doorway). The whole file:

`dockerfile

FROM python:3.12-slim

WORKDIR /app

COPY requirements.txt .

RUN pip install --no-cache-dir -r requirements.txt

COPY . .

EXPOSE 8000

CMD ["uvicorn", "main:app", "--host", "0.0.0.0", "--port", "8000"]

`

Build with docker build -t rag-api ., run with docker run -p 8000:8000 rag-api. One command, and your environment is reproducible forever. List docker on your CV only after this works — then list it proudly.

Deploy it: a URL anyone can click

Free and near-free tiers make shipping painless in 2026: Railway, Render, Fly.io, Hugging Face Spaces, or a small cloud VM — pick one and learn it. The universal checklist: set your API key as a platform environment variable (never in the image), include a /health route, and keep a persistent disk (or re-embed at startup) for your vector index. After deploy, your README gets its most important line: Live demo: https://your-app.example.com/docs. Every Module 4 project repeats this loop, so invest an extra hour now to make it smooth — deployment fluency is a compounding skill, and 'deployed' is the word that separates your portfolio from every course graduate who only has localhost.

Basic CI: tests on every push

One small GitHub Actions file and your repo starts proving itself:

`yaml

# .github/workflows/ci.yml

on: [push]

jobs:

test:

runs-on: ubuntu-latest

steps:

  • uses: actions/checkout@v4
  • uses: actions/setup-python@v5

with: {python-version: "3.12"}

  • run: pip install -r requirements.txt
  • run: pytest

`

Now every push runs your unit tests (you wrote them in Lesson 7), and a green checkmark appears on your repo. Recruiters may not read the YAML, but engineers do — and 'CI/CD' on your CV now has a public, clickable receipt. Lesson 12 adds your eval suite to this same pipeline.
