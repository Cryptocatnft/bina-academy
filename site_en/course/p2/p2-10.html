Building Your First Agent (No-Code)

🎯 What you'll be able to do: Build and test a working agent in a no-code platform — your first real artifact, live and demoable, by the end of this lesson.
Alex · Play the lecturer

Pick your platform

For a first agent in 2026, choose one of these:

  • Custom GPTs (ChatGPT) or Claude Projects — fastest start: system message + files + web access, shareable link. Great for knowledge assistants.
  • Zapier Agents — agents wired directly to thousands of app actions. Great when the agent should *do* things in other apps.
  • n8n or Make — visual workflows with an AI Agent node; the most 'real world' of the bunch and what many employers actually run. Slightly steeper curve.

Start with a Custom GPT or Claude Project today — build the brain first, connect the hands in Lesson 12. Pick based on what you'll demo, not what's trendy.

Define the job, then the brain

An agent needs a *specific* job, not a mission statement. Bad: "help me with my job search." Good: "answer interview prep questions for data analyst roles, using my CV, and give feedback." Write the job as one sentence with a noun and a verb, then build the system message with the six blocks from Lesson 8: identity, scope, style, grounding, guardrails, edge behavior. Upload grounding files — your CV, a knowledge base, a FAQ document. A knowledge-grounded agent beats a general one in every test that matters, and it's what employers check: *did you ground it?*

Give it one tool

Even in no-code, the tool is what makes it an agent and not a chatbot. Simplest meaningful toolset: web search (current information), file reading (analyze documents users upload), and in Zapier-style platforms, one real action — send an email, add a row to a sheet, create a calendar event. One is enough today. The discipline to learn: every tool is a permission. Before enabling it, ask what the agent could do with it on a bad day, and set limits — e.g. search yes, purchase no. Autonomy is earned; today's agent gets training wheels, and that's correct.

Test like a skeptic, then ship v1

Run your 10-message test set: 3 typical requests, 2 out-of-scope, 2 hostile or confusing, 2 knowledge questions it must answer *only* from your files, 1 impossible request. Watch where it fails; patch the system message; re-run. Then write a mini README: what the agent does, what it knows, what it may and may not do, and known limitations. Screenshot or record it working. Congratulations — that's your first portfolio artifact, and you'll list it as one. v1 shipped beats v2 imagined; you'll iterate it again in Module 4 with real polish.

Copy-ready prompt

Help me define my first agent. My context: [YOUR ROLE OR GOAL]. Give me: (1) a one-sentence specific job for the agent, (2) a draft system message under 200 words using the six-block structure, (3) a 10-message test plan with expected behavior for each.

Here is my agent's job: [DESCRIBE IT]. List the 3 highest-risk mistakes it could make with its tools, and one system-message rule to prevent each.

💪 Exercise

Build the agent: pick a platform, write the system message, upload at least one grounding file, enable one tool. Run a 10-message test set, patch twice, and write a 150-word README. Save the shareable link and screenshots in your course folder — this is portfolio artifact #1.
