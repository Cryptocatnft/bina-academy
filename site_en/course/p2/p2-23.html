Take-Home Assignments: Build a RAG or Agent Under Time Pressure

🎯 What you'll be able to do: Master the AI-engineering take-home — scope ruthlessly, build a working RAG or agent in hours not days, and submit with the README and trade-off notes that get you hired.
Alex · Play the lecturer

What they're really grading

A take-home rubric usually has four silent criteria: does it work (they will run it — a broken submission with great ideas scores below a working one with rough edges); is the code sane (small functions, error handling, no 400-line notebook exported as an app); did you make sensible trade-offs (documented choices beat hidden perfection); can I work with this person (README tone, commit hygiene). What loses points: frameworks you can't explain, no tests, no error handling on API calls, hardcoded keys, and — the classic — spending the whole budget on polish for one path while the main flow breaks on edge cases. Scope to the rubric: working end-to-end first, extras only if time remains.

The time-boxed plan

For a typical 'small RAG/agent, few days' assignment:

  • Hour 0 — read and scope. Extract explicit requirements into a checklist; identify the core loop and mark everything else 'nice to have.' Write the plan at the top of your README.
  • Hours 1–3 — walking skeleton. Data in → model call → answer out, deployed or runnable via one command. Ugly is fine; working is everything.
  • Hours 4–8 — quality pass. Pydantic outputs, retry on API calls, top-k retrieval with citations, a /health route. Reuse your Module 3 patterns — you've built this before.
  • Hour 9 — evals, minimum viable. 10 golden questions, pass rate printed. A take-home *with* an eval loop beats most of the pool.
  • Final hour — README and demo.

Stop when the plan says stop. Over-building reads as poor judgment, not dedication.

The two files that decide it

Reviewers open two files first: the README and your main module. README structure that wins: one-line description; 30-second quickstart (docker compose up); a short 'decisions & trade-offs' section — 'chunked on section headers at ~400 tokens because the docs have strong structure; used Chroma for zero-config local dev; single mini-model for cost; evals: 10 cases, 80% faithful (failures concentrated in table-heavy pages — noted, not fixed, for scope)' — that paragraph is where seniors are made. Then 'what I'd do with more time,' honestly, 3 items. The main module should read like the README promised: clean names, typed functions, try/except around anything that touches the network. And run gitleaks before pushing — a committed key in a take-home is an automatic fail at too many companies.

Presenting it and the follow-up call

After submission comes the review call — prepare like Lesson 22's drill: a 3-minute walkthrough (problem → design → demo → evals), and answers for the questions your README invites: 'why that chunk size?' 'how would this scale?' 'what broke?' Know your own numbers cold (eval pass rate, cost per query, latency) and volunteer one limitation before they find it — 'table extraction is the weak spot; I'd add a table-aware parser' — because finding your own bugs is exactly the senior signal they're grading. If the assignment demands more than ~8–10 hours for a junior role without pay, it's fair to ask about scope — companies that respect candidates respect the question.

Copy-ready prompt

Here is my take-home assignment: [PASTE BRIEF]. Extract the explicit requirements as a checklist, identify the core loop, and propose a time-boxed plan for [HOURS] hours — including what I will deliberately NOT build. Flag any requirement that is ambiguous enough to ask about.

Write the 'decisions & trade-offs' section of my take-home README from these notes: [PASTE YOUR CHOICES]. Honest engineer voice, one short paragraph plus a 'with more time' list of 3 items.

I finished my take-home (RAG over [DATASET], evals at [SCORE]). Give me the 10 hardest follow-up questions the reviewer will ask on the call, with strong 30-second answers grounded in my actual work.

💪 Exercise

Simulate one timed take-home: 4 hours, hard stop — 'build a mini RAG over 20 public FAQ pages with citations, an eval of 10 questions, and a README with trade-offs.' Follow the time-boxed plan exactly, push to GitHub, then have your Lesson 22 AI interviewer grill you on it. Not only is it practice — the repo itself becomes portfolio artifact five.
