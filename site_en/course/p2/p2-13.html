Project 1: Customer-Support Agent (LangGraph, Deployed)

🎯 What you'll be able to do: Build and deploy a complete customer-support agent with LangGraph — classification, RAG over FAQ docs, safe tool actions, human gate for refunds — your first portfolio-grade shipped project.
Alex · Play the lecturer

The design

One repo, one agent, four components you already know:

1. Classifier — structured output (Lesson 7): route each message to faq, order_status, or refund.

2. RAG node — your Lesson 9 engine over a real FAQ/knowledge base.

3. Tools — get_order_status, create_refund (function calling, Lesson 11).

4. Human gate — refunds above a threshold pause for confirmation; everything else flows.

In LangGraph terms: a classifier node with conditional edges to three branches, tool nodes, and a confirm node. This is a StateGraph with a recursion limit and checkpointer — you wrote that skeleton in Lesson 11. Now it does something a business would pay for: deflect tier-one support tickets with citations, and escalate the rest.

Build order that works

Build the boring way, test each layer before adding the next:

1. Data first: 30–50 real FAQ entries (use a public support docs page, or your own company's). Chunk, embed, load Chroma at startup.

2. Classifier with Pydantic schema — unit-test with 15 hardcoded messages (include typo'd and angry ones).

3. RAG node with [S#] citations and 'not in sources' behavior.

4. Tool nodes with mocked order data; log every call.

5. The refund gate: pending_refunds in state, a /confirm endpoint, and a message to a human channel (even just a log line for the demo).

Each step is small and provable — that's how professionals de-risk a build, and how your git history tells a story an engineer will respect.

Ship it with evals attached

Deployment repeats the Lesson 10 loop: FastAPI app, /chat and /health endpoints, Dockerfile, free-tier deploy, CI on push. What makes this portfolio-grade rather than a course exercise:

  • Evals in CI (Lesson 12): a 30-case golden set — routing accuracy, answer faithfulness, refund-gate correctness — with the pass rate in the README.
  • A demo script: 3 example conversations in the README showing escalation, RAG citation, and the human gate.
  • A trace sample: one logged agent run, pretty-printed — proof you can debug what you ship.
  • Cost note: 'gpt-4o-mini, ~$0.002 per ticket' — engineering judgment on display.

README, code, live link, eval table: that's the full professional package.

The story you tell

This project maps directly onto the 2026 market: LangGraph (13% of agentic postings), RAG (26%), tool use (11%), evals (9%), Docker + cloud (34%). In interviews it becomes your anchor story: 'I built a support agent with a classification-to-action pipeline, grounded answers with citations, a human gate on refunds, and an eval suite in CI — deployed, here's the link.' Structure it as situation → design choices → one real bug you traced with logs → eval numbers before/after a fix. Next lesson: project two, document intelligence with RAG — the same engine pointed at higher-value data.
