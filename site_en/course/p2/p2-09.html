What an Agent Actually Is

🎯 What you'll be able to do: Understand the agent loop — model, tools, memory, decisions — and see how it differs from a chatbot and why it's the center of AI work in 2026.
Alex · Play the lecturer

The agent loop

A chatbot answers, then waits. An agent runs a loop:

1. Perceive — read the task and current state.

2. Decide — the model chooses the next action: call a tool, ask the user, or finish.

3. Act — execute: search the web, read email, run code, update a spreadsheet.

4. Observe — feed the result back in.

5. Repeat until done.

That loop — decide, act, observe — is the entire secret. Everything called 'agentic AI' in 2026, from coding agents to support automation, is this loop with different tools plugged in. Master the loop and you can build any of them.

Brain, hands, and notebook

Three components make the loop work:

  • The model (brain): chooses actions and interprets results. Reasoning models make better decision-makers; fast models are fine for simple flows.
  • Tools (hands): functions the agent can call — search, email, calendar, database, file operations, even other agents. Lesson 11 covers how tools are defined.
  • Memory (notebook): anything that survives between steps — a summary of what's been done, a checklist of goals, or long-term storage like a vector database. Without memory, agents repeat themselves; without tools, they just talk.

Autonomy level is the fourth dial: from 'suggest every action, human approves' to 'full auto within guardrails.' Start low; earn trust; raise gradually.

Agents vs. chatbots vs. automations

Three cousins worth separating:

  • Chatbot: text in, text out, human drives every step.
  • Classic automation (a Zapier flow): fixed path — when email arrives, forward to Slack. Reliable, dumb, can't handle surprises.
  • Agent: the model *decides the path*, handling cases you didn't script.

The tradeoff is flexibility versus predictability. That's why the winning 2026 pattern is the hybrid: deterministic automation for the routine 90%, an agent for the weird 10%, humans for the exceptions. Knowing when *not* to use an agent is a more valuable skill than building one — it's the difference between a demo and a system that runs for a year.

Why this is the job market

Titles like AI Automation Specialist, AI Ops, and AI Solutions Engineer are, underneath the branding, *agent work*: understand a business process, decide which parts to automate deterministically, where the agent goes, and what guardrails it needs. The skills stack directly from this course — prompt engineering (Module 2), tool connections (Lesson 12), and the four portfolio projects (Module 4) are all agent builds. An agent you can demo in an interview, with a README explaining your autonomy and guardrail choices, is worth more than any certificate alone. You'll have five.

Copy-ready prompt

Here is a business process: [DESCRIBE A PROCESS — e.g. 'handling new customer emails at a small company']. Break it into steps and mark each one: (a) fixed rule/automation, (b) needs judgment → agent step, (c) human only. Explain each choice in one line.

I want to build an agent that [GOAL]. List: the 3-5 tools it would need, what it should never be allowed to do, and where a human checkpoint should be. Format as three short lists.

💪 Exercise

Pick one recurring task in your week (personal or work). Write its agent loop on paper: the goal, the tools it needs, what it must remember between steps, and the guardrails. Then mark the two riskiest decisions it would make — those are your human checkpoints.
