Why RAG exists

Two problems, one solution. Models don't know your private data, and context windows choke on whole archives. RAG fixes both: at index time, split documents into chunks, convert each to an embedding (a vector of numbers where similar meanings sit close together), and store them in a vector database. At query time, embed the user's question, find the nearest chunks, and paste only those into the prompt as context. The model now answers from fresh, specific, *citable* sources — hallucinations drop, and you can show exactly which paragraph produced the answer. That's the whole idea; everything else is engineering.

Chunking: the underrated skill

Chunk size decides RAG quality. Too small: you retrieve fragments without context. Too big: noise dilutes the signal and costs tokens. Start around 300–500 tokens with 10–15% overlap, and — the pro move — chunk on structure: headers, paragraphs, or sections, not arbitrary character counts. A basic splitter:

`python

def chunk(text: str, size: int = 400, overlap: int = 50) -> list[str]:

words = text.split()

return [" ".join(words[i:i+size])

for i in range(0, len(words), size - overlap)]

`

Always attach metadata — source file, heading, page — or your answers can't cite. Interview classic: 'how would you chunk a 200-page PDF with tables?' Have an opinion.

Embeddings and the vector DB

An embedding model maps text to a point in space where meaning = distance: 'refund policy' lands near 'money-back guarantee', far from 'kubernetes'. OpenAI's text-embedding-3-small or open alternatives both work fine. Store vectors in a vector DB — Chroma for local dev, pgvector for Postgres shops, Pinecone for managed scale:

`python

import chromadb

db = chromadb.PersistentClient(path="./rag_data")

col = db.get_or_create_collection("docs")

col.add(documents=chunks, ids=[str(i) for i in range(len(chunks))])

hits = col.query(query_texts=[question], n_results=4)

`

Top-k similarity search (k=3–5) returns the chunks you paste into the prompt. Vector DBs are in 13% of agentic postings — this is that skill.

The grounded answer loop

The final pattern, combining everything from Modules 2 and 3:

`python

context = "\n\n".join(

f"[S{i+1}] {c}" for i, c in enumerate(hits["documents"][0])

)

prompt = (f"Answer ONLY from the sources. Cite [S#] after each claim. "

f"Say 'not in sources' if absent.\n\n{context}\n\nQ: {question}")

`

Then the discipline that separates pros from demo-builders: test it. Keep 20 golden questions with known answers; when you change chunk size, model, or top-k, re-run and compare (Lesson 12 makes this automated). Bad retrieval is silent — only evals catch it.
