GitHub Portfolio Polish (README, Demo Links)

🎯 What you'll be able to do: Turn your four project repos into a recruiter-ready portfolio — profile README, pinned repos, consistent quality bar, and demo links that work when clicked at 2am.
Alex · Play the lecturer

The profile: your landing page

github.com/you is a landing page — treat it like one. Create a profile README (a repo named exactly like your username): two lines on who you are ('AI engineer — I build and deploy agents, RAG systems, and MCP tools'), the four projects as a linked list with one-line descriptions, stack keywords in compact badges, and links to LinkedIn and your demo video. Then pin the four project repos (not your practice repos). Set your contribution graph visible — a few months of consistent commits is quiet proof of momentum. Check everything in an incognito window: what a stranger sees in 30 seconds is the only thing that counts.

The repo quality bar

Each project repo must pass this checklist, no exceptions:

  • Hook line: 'Customer-support agent: classifies, retrieves, answers with citations, human-gated refunds — deployed.'
  • Live demo link at the top — tested this week, and a screenshot or GIF right below it (links die; screenshots don't).
  • Quickstart that actually runs: cp .env.example .env, docker compose up, done.
  • Architecture note: 4–6 lines or a simple diagram — FastAPI → LangGraph → Chroma → evals in CI.
  • Eval table in the README with dates.
  • License file (MIT).

The polish pass: archive or make private the tutorial repos, fix the broken READMEs you'd be embarrassed by, and remove any file named final_v2_REAL.py. Your history is fine — messy *front doors* are not.

Demo links that survive 2am

A recruiter clicking your link at 2am must see something working. Free-tier apps sleep — so: add a warm-up or a fast cold start, a friendly loading state, and a static fallback: a pre-run demo page or recording for when the live demo hiccups ('Live demo — if it's sleeping, watch the 90-second video'). Keep two sample datasets pre-loaded in every app (Lesson 14 rule) so no link ever shows an empty screen. Then monitor: put a /health check on a free uptime monitor so you get an email before a recruiter gets an error page. 'Deployed and maintained' is the whole message — the difference between a portfolio and a graveyard is whether the links work six months later, and interviews are exactly when you find out.

The portfolio site (optional but strong)

One page that ties it together — GitHub Pages is free: your one-liner, the four projects with screenshots and live links, the demo video, and contact. Design bar: clean and readable, not fancy — dark-mode-friendly, mobile-friendly, no frameworks needed. If you built the multi-agent content pipeline (Lesson 15), let it write your first drafts — dogfooding your own AI system is itself a talking point. Cross-link everything: site → repos → LinkedIn → CV. When Module 6's applications ask for 'portfolio URL,' this is the link you give. One hour of assembly, permanent professional presence.

Copy-ready prompt

Review my GitHub profile like a hiring engineer with 30 seconds: [PASTE PROFILE README + LIST OF REPOS]. Score it, list what's confusing, and give me the 5 highest-impact fixes.

Write hook lines (one sentence each) for my four project repos: support agent, document analyzer, multi-agent pipeline, personal assistant with MCP. Make each concrete with one number or capability — no adjectives.

Create a README quality checklist I can run against any repo, in table form, with pass/fail criteria: hook, demo link, screenshot, quickstart, architecture, evals, license. Then apply it to [PASTE MY README] and report gaps.

💪 Exercise

Do the full polish pass: profile README, four pinned repos upgraded to the quality bar, all demo links tested (fix or add fallbacks), messy repos archived, and optionally the portfolio site. Then send your GitHub URL to one person outside tech and ask what they think you do — if they can't tell, fix the top of the profile. Module 6 starts the actual hunt.
