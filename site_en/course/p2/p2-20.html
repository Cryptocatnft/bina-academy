Building Your Online Presence: GitHub and Portfolio

🎯 What you'll be able to do: Assemble a public, credible presence — a portfolio site and a GitHub profile — that lets employers verify and test your work in minutes.
Alex · Play the lecturer

The portfolio site: one page, five projects

One page is enough — recruiters spend 90 seconds, so design for the skim. Structure:

  • Header: name, target title, one line of positioning, links (LinkedIn, GitHub, email).
  • Projects — each with a 2-line pitch, a screenshot or short GIF, and three links: live demo, source, README. Order by strength, best first.
  • About: 3 sentences, human, with your course and certificate verification number once you have it (Lesson 24).

Build it wherever is fastest in 2026 — GitHub Pages, Carrd, Notion site, or an AI site-builder; the platform is irrelevant, the *working links* are everything. Test every link on your phone. A dead demo link reads as a dead project.

GitHub for the non-programmer

Even with zero-code projects, GitHub is where technical evaluators look — it signals you speak their culture. The minimum viable GitHub:

1. Real name or consistent handle, photo, bio with target title ('Building AI agents — n8n, Zapier, LLMs').

2. One repo per project — even if the 'code' is mostly JSON exports, prompts, and READMEs. That's legitimate: your prompts, schemas, and test logs *are* the artifacts.

3. A serious README per repo: what it does, architecture, screenshots, design decisions, test results, limitations. Pin your best repos.

4. Green squares help but aren't required — a handful of solid repos with excellent READMEs beats a year of commit noise.

Lesson 23's take-home training will feel familiar if take-homes involve repos — many do. You're pre-building that muscle now.

The connecting tissue

Credibility compounds when everything cross-links. Checklist:

  • Consistent identity: same name, same photo, same title across LinkedIn, GitHub, and the site — search engines and recruiters both reward coherence.
  • Links everywhere: LinkedIn Featured → site and repos; site → LinkedIn; every README → live demo; your CV's Projects section → all of it.
  • Working screenshots: images that load fast and show the *thing working*, not abstract diagrams.
  • Google yourself (incognito): what actually appears? Fix the top five results you control.

Also set up a professional email on your domain if you have one — name@yourdomain beats name1234 in 2026's trust economy, and it's a 10-minute job.

Presence as a habit

The site is a living artifact, not a one-time chore. Keep a build log — every new project, course milestone, or interesting automation gets a short entry (this pairs perfectly with your Lesson 15 pipeline, which can draft these). Update the site monthly: swap in the newest project, refresh numbers in your results ('12 agents shipped', '40% faster triage'). Small consistent public evidence beats sporadic brilliance — six months of a visible build log is a track record, and a track record is the single most convincing object in the 2026 job market, because it's the one thing that can't be faked in an interview. You've been building one all course. Now it's public.

Copy-ready prompt

Here are my five projects with one-line descriptions: [LIST THEM]. Write the copy for a one-page portfolio: a positioning line, a 2-line pitch per project in priority order with suggested screenshots, and a 3-sentence About. Human tone, no buzzwords.

Review this README like a technical hiring manager deciding in 90 seconds: [PASTE README]. What's missing? What would make me doubt the project is real? Give me the 3 highest-impact fixes.

💪 Exercise

Ship the public layer: one-page portfolio site with all projects linked, GitHub account with a repo and serious README for your best project, consistent identity across all three surfaces, every link tested on mobile. Google yourself in incognito and note what a recruiter sees.
