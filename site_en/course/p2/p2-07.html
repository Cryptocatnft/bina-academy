Chain-of-Thought — and When NOT to Use It

🎯 What you'll be able to do: Apply step-by-step reasoning where it pays off, use reasoning models wisely, and skip the overhead when it just wastes time and money.
Alex · Play the lecturer

What chain-of-thought does

Chain-of-thought (CoT) means asking the model to work through a problem step-by-step before giving the final answer: "List the constraints, check each one, then conclude." Why it works: the model's next-token prediction gets *better material* to predict from — each intermediate step becomes context that steers the rest. Effects: dramatically better on math, logic, comparisons, multi-step planning, and anything with constraints. Slightly worse on nothing — except speed and cost. CoT is how a pattern-completion machine borrows a scratchpad, and it's the single biggest quality trick in classic prompting.

Reasoning models changed the game

Since late 2024, frontier labs ship reasoning models that do extended internal thinking before answering — the model does CoT on its own, better than we can prompt for it. In 2026 the practical rule is: hard problem, use a reasoning model and simply ask the question; easy or bulk problem, use a fast model and don't ask for thinking. What's obsolete: pasting "think step by step" into every prompt out of ritual. What's still yours: decomposing the *problem* — breaking a big ask into ordered subtasks, deciding which model handles each, and defining what 'good' looks like. That judgment is the job.

When NOT to use reasoning

Skip the thinking when:

  • The task is retrieval or style — summarizing, rewriting, classifying well-known categories. Reasoning adds latency, not accuracy.
  • You're running at scale — 10,000 rows through an API: extra thinking tokens multiply cost by 3-10x.
  • Latency matters — chatbots and real-time UX feel dead above a second or two.
  • The reasoning is yours to give — if *you* can supply the checklist or rubric, a fast model with your structure beats a smart model guessing at your intent.

"Right-size the thinking" is a phrase that impresses interviewers. Use it.

Hybrid patterns for real work

The professional pattern is routing: a cheap fast model triages every input — is this simple or hard? Hard ones go to a reasoning model; simple ones get instant answers. You'll build exactly this in Module 4. Two more patterns: verify with a different mind — have a reasoning model check a fast model's output; and structured reasoning — "give me your final answer as JSON, with your key reasoning steps in a reasons field" — thinking you can audit, not just trust. Reasoning you can see beats reasoning you hope happened.

Copy-ready prompt

Solve this problem step-by-step. First list the constraints, then check each option against them, then eliminate, and only then state your final answer. Problem: [YOUR PROBLEM — budget, plan, comparison, or decision]

You are a quality checker. Here is a task and an AI's answer: [PASTE TASK AND ANSWER]. Work through it step by step, list every error or unsupported assumption, then verdict: CORRECT / NEEDS FIX with the fix.

💪 Exercise

Find a real decision you need to make (a purchase, a plan, a tradeoff). Ask a fast model directly, then ask a reasoning model (or use CoT prompting) on the same question. Compare answer quality, response time, and length. Write 3 sentences on when you'd pay the reasoning cost.
