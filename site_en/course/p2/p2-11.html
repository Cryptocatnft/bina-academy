Function calling: the atom of agency

Give the model a menu of tools and it chooses: that's function calling. You describe each function — name, purpose, parameters as JSON schema — and the model replies not with text but with a tool request. Your code executes it and feeds the result back:

`python

tools = [{

"type": "function",

"function": {

"name": "get_order",

"description": "Fetch order status by ID",

"parameters": {"properties": {

"order_id": {"type": "string"}}, "required": ["order_id"]},

},

}]

`

The loop — model picks a tool → you run it → result goes back → model continues — is the whole mechanism of ChatGPT's own features and every agent you'll ever build. Everything else is orchestration around this loop. Tool use is 11% of agentic postings; this is that skill, at the metal.

LangGraph: agents as state machines

A naive agent loop spirals: infinite retries, lost context, unbounded cost. LangGraph (in 13% of agentic postings) models the agent as a graph — nodes are steps (call model, run tool, human check), edges are transitions, and a state object carries the data. Key disciplines: conditional edges (route on the model's tool choice), a recursion limit (hard cap on steps), and checkpoints (persist state so a long agent survives restarts and can be replayed):

`python

from langgraph.graph import StateGraph

g = StateGraph(AgentState)

g.add_node("model", call_model)

g.add_node("tools", run_tools)

g.set_entry_point("model")

g.add_conditional_edges("model", route, {"tools": "tools", "end": END})

app = g.compile()

`

LangChain (15% of postings) supplies the surrounding ecosystem — model wrappers, retrievers, prompts. You'll use both; understand the graph underneath.

MCP: the universal tool port

Model Context Protocol is 2026's answer to tool chaos: a standard way to expose tools, resources, and prompts to any MCP-capable client — one server, every model. At 27% of agentic postings, it's the fastest-rising skill in the index. You can write an MCP server in a few lines and your tools instantly plug into Claude, Cursor, and countless agents:

`python

from mcp.server.fastmcp import FastMCP

mcp = FastMCP("support")

@mcp.tool()

def get_order(order_id: str) -> dict:

"""Fetch order status by ID."""

return orders.get(order_id, {"status": "unknown"})

`

Mental model: function calling is the *mechanism*; MCP is the *port standard* — USB for AI tools. Interviewers increasingly ask 'what is MCP and why does it matter?' — and now you can whiteboard it.

Designing agents that don't embarrass you

The difference between a demo and a system:

  • Small tool sets — 3–6 sharp tools beat 30 vague ones; models confuse themselves with too many.
  • Good descriptions — tool docs are prompts; 'Fetch CURRENT order status from the orders DB, not history' saves hours.
  • Hard limits — recursion cap, token budget, timeout. Agents must be able to *stop*.
  • Tracing — log every step (model call, tool, result); Lesson 12 makes it observable.
  • Human gates for irreversible actions — refunds, deletes, emails get a confirmation node.
