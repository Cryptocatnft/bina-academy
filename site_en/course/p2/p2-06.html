Few-Shot Patterns: Teaching by Example

🎯 What you'll be able to do: Use example-driven prompting to lock in format, tone, and judgment — and know exactly how many examples any task needs.
Alex · Play the lecturer

Show, don't tell

Zero-shot means instructions only: "Classify the sentiment of this review." It works for easy tasks. Few-shot adds worked examples: here's a review, here's exactly how I want it classified, and here's my label. Models are imitation machines — a concrete example encodes more information per token than a rule ever can. "Be concise and friendly" is vague. Two examples of a concise, friendly reply are a spec. Rule of thumb: the more your task involves *style, format, or judgment*, the more examples beat instructions.

Designing a good example set

A strong few-shot set is small — 2 to 5 examples usually. Beyond that you burn context and returns flatten. Choose them like test cases:

  • One typical case — the happy path.
  • One or two edge cases — the ambiguous ones where you show the judgment call you want.
  • Optionally one exception case — showing what to output when the task doesn't apply.

Keep every example in exactly the same format — the model copies your inconsistencies as faithfully as your rules. Diversity matters: five near-identical examples teach almost nothing.

Patterns worth stealing

  • Format-lock: 2 examples of your exact output shape before asking for the real thing.
  • Contrast pairs: show a bad output and a good output for the same input — "like this, not like that."
  • Escalation examples: in a support agent, include one example of *politely refusing* something and one of *escalating to a human* — the model learns the boundaries, not just the happy path.
  • Synthetic few-shot: ask the AI to generate candidate examples for your task, curate the good ones, then use them as your few-shot set. AI building prompts for AI — very on-brand for this course.

Each pattern transfers directly to the agents you'll build in Module 3.

When few-shot isn't worth it

Few-shot costs tokens, money, and clarity. For trivial tasks — "translate to English," "fix this typo" — zero-shot is fine and cheaper. For heavy factual tasks, examples help less than *grounding* (giving source text). And beware the classic trap: a flawed example poisons everything — the model will reproduce your typo or your bias at scale, obediently. Audit your examples like code. The final test: run your prompt on 5-10 fresh inputs and see if outputs match the examples. If yes — ship it. If not — add an edge-case example and retry.

Copy-ready prompt

Classify each support message, following the pattern of these examples: Input: "Where is my order #1234?" → {"category": "order_status", "sentiment": "neutral", "escalate": false} Input: "This is the THIRD time it's broken, I'm furious!" → {"category": "complaint", "sentiment": "negative", "escalate": true} Now classify: [PASTE MESSAGES, one per line]. Return JSON lines only.

I want you to [YOUR TASK, e.g. 'write product descriptions in my style']. Generate 5 diverse example input-output pairs for this task. I will pick the best ones to use as few-shot examples. Present them as a numbered list: Input → Output.

💪 Exercise

Pick a recurring writing or classification task of yours. Build a few-shot prompt with 3 examples — one typical, one edge case, one exception. Test it on 5 new inputs. Then run the same task zero-shot and compare. Write down what the examples fixed.
