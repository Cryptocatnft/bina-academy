Your first API call

An API key turns a chat product into a programmable engine. Get a key from OpenAI or Anthropic, store it as an environment variable (export OPENAI_API_KEY=...), and call the model in about five lines:

`python

import os

from openai import OpenAI

client = OpenAI() # reads OPENAI_API_KEY automatically

resp = client.chat.completions.create(

model="gpt-4o-mini",

messages=[{"role": "user", "content": "Explain RAG in one sentence."}],

)

print(resp.choices[0].message.content)

`

The same pattern works for Claude (anthropic SDK), Gemini, and open models. Never hardcode keys in code — keys leaked to GitHub get scraped in minutes. In Lesson 8 you'll add .env to .gitignore before it bites you.

Tokens, temperature, and cost control

APIs bill by token — roughly a word chunk — with input and output priced separately. A big prompt with a long pasted document can cost more than the answer is worth. Professional cost control: pick the cheapest model that works (mini variants for bulk tasks), cap max_tokens on outputs, and cache: repeated identical prompts can hit prompt-caching and cost a fraction. Watch your usage dashboard the first week until you internalize the economics. Also know temperature: near 0 for deterministic extraction (Lesson 7), higher for creative writing. Choosing model + parameters per task is a real, paid engineering decision — interviewers ask it.

Retries, rate limits, and failure

The real internet fails: 429 rate limits, 500s, 30-second timeouts. Production code retries:

`python

import time

def call_with_retry(fn, attempts=4):

for i in range(attempts):

try:

return fn()

except Exception as e:

if i == attempts - 1:

raise

wait = 2 ** i # 1s, 2s, 4s

time.sleep(wait)

`

This is exponential backoff, and every serious AI codebase contains some version of it. The SDKs have built-in retry options too — know both. If your take-home assignment (Lesson 23) has no retry logic, reviewers notice. If it has it, they know you've been in production.

From one call to a loop

One call is a demo; systems are loops. Real pipelines call the model per item, track failures, log costs, and process in batches with a queue if volume grows. Sketch of the loop you'll build all course:

`python

results = []

for msg in messages:

try:

results.append(call_with_retry(lambda: classify(client, msg)))

except Exception as e:

results.append({"error": str(e), "input": msg})

`

Note the pattern: keep the input with the error so nothing is lost. Add print(f"{i}/{len(messages)}") progress logging and you have the skeleton of every batch job, evaluator, and agent step you'll write in this course.
