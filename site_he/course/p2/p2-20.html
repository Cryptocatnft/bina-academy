ניקיון שמראה בוגר

לפני שמפרסמים, עוברים סדרת ניקיון: (1) שמות קבצים ברורים — agent.py ולא final2.py; (2) מחיקת מתים — קבצי ניסוי, פלטים, דברים שלא בשימוש; (3) משתני סביבה — .env.example עם שמות המפתחות בלי ערכים, ובקוד קריאה מסביבה בלבד; (4) requirements.txt עדכני — התקנה נקייה בסביבה חדשה חייבת לעבוד; (5) הודעות קומיט — אם ההיסטוריה מביכה ("asdf", "שיפורים!!!"), בסדר לכתוב מחדש את ההתחלה במאגר חדש — מגייסים לא מזהים בתולדות הקומיט, הם קוראים את מה שמונח לפניהם; (6) לינטר — ruff check . בסיסי מספיק, קוד שעובר לינט נראה מקצועי גם למי שלא קורא אותו.

פרופיל GitHub ופין

פרופיל GitHub עם README אישי (מאגר בשם המשתמש שלכם) — שורת מיצוב, מה אתם בונים, לינק ללינקדאין, וארבעת הפרויקטים בטבלה עם לינקים לדמו. פינים (pinned repositories) — ששת המקומות בראש הפרופיל: שימו שם רק את הפרויקטים המוגמרים, מהטוב לפחות — לא תרגילים, לא פורקים של אחרים. מגייסים מסתכלים דווקא שם. בעברית או אנגלית? הקוד וה-README — באנגלית (מעסיקים גלובליים קוראים); לינקדאין והפניות — לפי הקהל. ואם אתם שואלים אם מותר פרויקט קורס בתיק — שאלה הפוכה: מותר לא לשפר אותו אחרי הקורס? השיפורים שתעשו עכשיו הם בדיוק מה שמבדל אתכם.
