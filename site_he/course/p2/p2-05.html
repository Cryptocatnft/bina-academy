סביבת עבודה: venv ו-pip

לפני שכותבים קוד — סביבה נקייה. virtualenv הוא תיק שמכיל את כל החבילות של הפרויקט שלכם, מנותק מהשאר, כך שפרויקט אחד לא שובר את השני. pip הוא מתקין החבילות. בטרמינל:

`bash

python3 -m venv .venv

source .venv/bin/activate # Windows: .venv\Scripts\activate

pip install requests

`

כשהסביבה פעילה רואים (.venv) בשורת הפקודה. חשוב: קובץ requirements.txt עם רשימת החבילות (אפשר לייצר עם pip freeze > requirements.txt) — זה מה שמאפשר למישהו אחר, כמו למשל המראיין שלכם, להריץ את הקוד שלכם.

משתנים, טיפוסים ומחרוזות

`python

name = "נועה" # מחרוזת (str)

salary = 28000 # מספר שלם (int)

success_rate = 0.87 # מספר עשרוני (float)

is_remote = True # בוליאני (bool)

print(f"{name} מרוויחה {salary:,} ש"ח")

`

ב-LLM בעבודה, כמעט הכול זה מחרוזות: הפרומפט שאתם שולחים, התשובה שחוזרת. f-strings (ה-f לפני המרכאות) מאפשרים להזריק משתנים לתוך טקסט — תשתמשו בזה אלף פעמים. שימו לב לניקוד מחרוזות ולמרכאות כפולות בתוך עברית ואנגלית מעורבת — מקור קלאסי לשגיאות.

רשימות ומילונים: הדלק והתיק של AI

רשימות — סדרה של דברים; מילונים — זוגות מפתח-ערך:

`python

messages = [

{"role": "user", "content": "שלום!"},

{"role": "assistant", "content": "מה נשמע?"},

]

user = {"name": "דנה", "tickets": 12, "plan": "pro"}

print(user["plan"]) # pro

print(len(messages)) # 2

`

שימו לב למבנה messages: רשימה של מילונים עם role ו-content — זה בדיוק הפורמט שכל API של LLM מקבל. כל שיחה עם מודל, בכל SDK, נראית כך. כשתבינו רשימות ומילונים — הבנתם את מבנה הנתונים של כל תעשיית ה-AI.

פונקציות: קוד שאפשר להשתמש בו שוב

`python

def estimate_cost(tokens: int, price_per_1k: float = 0.005) -> float:

"""מחשב עלות משוערת של קריאה ל-LLM."""

return tokens / 1000 * price_per_1k

print(estimate_cost(12000)) # 0.06 דולר

`

פונקציה לוקחת קלטים, מחזירה פלט, ולא מערבבת את עצמה בקוד שמסביב. def מגדיר, שם הפונקציה באנגלית, פרמטרים עם טיפוסים, ומחרוזת תיעוד (docstring). מספיק לכם זה. בעולם אמיתי תכתבו בעיקר פונקציות קצרות שקוראות ל-API-ים ומעבדות טקסט — בדיוק מה שנעשה בשיעור הבא.
