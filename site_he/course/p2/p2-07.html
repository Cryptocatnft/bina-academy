נועה · השמע את המרצה

למה JSON ולא טקסט חופשי

כשקוד צריך להמשיך אחרי ה-AI — לשמור במסד, לשלוח מייל, להציג כרטיס — הוא צריך מבנה יציב. טקסט חופשי שבור מההתחלה: פעם השם ראשון, פעם במרכאות, פעם עם הקדמה מנומסת "בוודאי, הנה...". הפתרון: לדרוש JSON — פורמט של מפתחות וערכים שפרסר מבין. כל מודל מוביל תומך במצב מובנה, והשילוב של "סכמה + ולידציה" הוא הבסיס לכל אינטגרציה אמיתית בין LLM למערכות.

JSON mode בפועל

`python

resp = client.chat.completions.create(

model="gpt-4o-mini",

messages=[{"role": "user", "content":

"חלץ מהטקסט: name, email, urgency (1-5). החזר JSON בלבד."}],

response_format={"type": "json_object"},

)

import json

data = json.loads(resp.choices[0].message.content)

print(data["email"])

`

הטריק הכי חשוב: לכתוב בפרומפט את הסכמה המדויקת — שמות שדות, טיפוסים, ערכים מותרים — ולהגיד במפורש מה לעשות כשמידע חסר (null, לא המצאה). מודל ממיר טקסט לנתונים בצורה מדהימה — אבל רק כשמגדירים לו בדיוק לאן.

Pydantic: ולידציה שמירה היא לא אופציה

גם ב-JSON mode מודלים שולחים מדי פעם שטויות — שדה חסר, אימייל במקום מספר. pydantic בודק כל תשובה מול הגדרת טיפוסים:

`python

from pydantic import BaseModel, EmailStr, Field

class Ticket(BaseModel):

name: str

email: EmailStr

urgency: int = Field(ge=1, le=5)

ticket = Ticket.model_validate_json(raw) # זורק שגיאה אם לא תקין

`

אם זה עבר — הנתונים מובטחים; אם לא — תופסים את השגיאה ושולחים שאלה מתקנת. עם pydantic אפשר גם לייצא את הסכמה ולהעביר אותה ל-API ישירות. זה התחתית של כל pipeline אמין.

פלט נכשל? נסה שוב בחכמה

כשהוולידציה נופלת, לא מוותרים — מאכילים את המודל בשגיאה שלו:

`python

try:

ticket = Ticket.model_validate_json(raw)

except ValidationError as e:

fix = call_llm(f"התשובה הזאת לא תקינה: {e}. תקן והחזר JSON בלבד: {raw}")

ticket = Ticket.model_validate_json(fix)

`

לולאת "נסה-ולידציה-תקן" מעלה את אחוזי ההצלחה מ-95% ל-99.9% — וזה בדיוק ההבדל בין דמו לפרודקשן. בכל ראיון LLM Engineer שאלו אותי על הלולאה הזאת.
